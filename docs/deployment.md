# Deployment Runbook

How to run the Adaptive Learning Platform locally and how to deploy it to a
free-tier cloud stack. Written to be followed top to bottom by someone who has
only just cloned the repository.

## 1. Execution environments

| | Local development | Cloud deployment |
|---|---|---|
| Backend | Docker Compose (`python:3.11-slim`) | Render web service (Docker) |
| Database | `pgvector/pgvector:pg15` container | Render Postgres 15 (free plan) |
| Frontend | Vite dev server, port 5173 | Vercel static hosting + CDN |
| Search | SearXNG container | Not deployed — `/references` degrades |
| RAG embedding | Enabled (`sentence-transformers`) | Disabled (slim image) |
| LLM | Groq API (`openai/gpt-oss-20b`) | Same |

The two differences worth understanding before deploying are in §5.

## 2. Prerequisites

- Docker Desktop, running
- Node.js 18 or newer
- A Groq API key — free from [console.groq.com](https://console.groq.com)

## 3. Local deployment (Docker Compose)

```bash
git clone https://github.com/its-wasp/personal-adaptive-tutor.git
cd personal-adaptive-tutor
cp .env.example .env
```

Edit `.env` and set `GROQ_API_KEY` and `JWT_SECRET`. Every other default works
as-is for local use.

```bash
docker compose up
```

Three containers start: `db`, `searxng`, `backend`. On first boot the backend
entrypoint prints `[entrypoint]` lines as it:

1. waits for Postgres to accept connections (up to 60s — `depends_on` does not
   wait for readiness, only for the container to exist),
2. runs `alembic upgrade head`, which creates the `vector` extension and all
   13 tables,
3. seeds the 25-concept DSA knowledge graph.

Steps 2 and 3 are idempotent; later starts skip them. Wait for
`Application startup complete`.

```bash
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>, sign up, and complete onboarding.

### Verify the stack

```bash
curl http://localhost:8000/health        # {"status":"ok"}
curl http://localhost:8000/health/db     # {"status":"ok","database":"connected"}
python backend/scripts/smoke_test.py     # exercises every endpoint end to end
```

The smoke test signs up throwaway users, drives the full chat and quiz flow,
and asserts that a second account cannot reach the first one's data. A non-zero
exit means something is wrong; each step prints PASS or FAIL.

### Optional: seed RAG reference content

```bash
docker compose exec backend python -m app.rag.content_seeder
```

Generates three explanation variants per concept and embeds them into pgvector.
Roughly 10 minutes for all 25 concepts — it sleeps between calls to stay inside
Groq's free-tier rate limit. Safe to interrupt and re-run.

### Local without Docker

The entrypoint's work has to be done by hand:

```bash
cd backend
pip install -r requirements.txt
alembic upgrade head
python -m app.data.seed_graph
uvicorn app.main:app --reload
```

This needs a Postgres reachable at the `POSTGRES_*` values in `.env`, with the
`vector` extension available.

## 4. Cloud deployment

Backend and database on Render, frontend on Vercel. Both fit inside free tiers.

### Ordering

The two halves reference each other: the frontend needs the API's URL, and the
API's CORS allowlist needs the frontend's URL. Neither exists at the start, so
deploy in this order:

1. Render backend → obtain the API URL
2. Vercel frontend, with `VITE_API_URL` set to that URL → obtain the site URL
3. Set `CORS_ORIGINS` on Render to the site URL → redeploy the backend

Skipping step 3 produces a frontend that loads but whose every request fails a
CORS preflight in the browser.

### 4a. Backend and database (Render)

1. Render dashboard → **New** → **Blueprint**, and point it at this repository.
   It reads [`render.yaml`](../render.yaml) and proposes a web service plus a
   Postgres instance.
2. Render prompts for the two values held back from the repo:
   - `GROQ_API_KEY` — your key
   - `CORS_ORIGINS` — leave blank for now; filled in at step 3
3. Apply. The first build takes a few minutes.

`DATABASE_URL` is wired automatically from the database resource, and
`JWT_SECRET` is generated by Render — neither is ever committed.

On boot the entrypoint migrates and seeds exactly as it does locally. Confirm
with `curl https://<your-service>.onrender.com/health/db`.

### 4b. Frontend (Vercel)

1. Vercel → **Add New** → **Project**, import the repository.
2. Set **Root Directory** to `frontend`. This is required —
   [`frontend/vercel.json`](../frontend/vercel.json) is only picked up from
   there, and it carries the SPA rewrite that keeps `/chat/:id` working on a
   hard refresh.
3. Add an environment variable: `VITE_API_URL` = the Render service URL, with
   no trailing slash.
4. Deploy.

Vite inlines `VITE_*` at build time, so changing that variable later requires a
new deploy, not just a restart.

### 4c. Close the CORS loop

Back on Render, set `CORS_ORIGINS` to the Vercel URL
(`https://your-app.vercel.app`) and redeploy. Multiple origins are
comma-separated. `localhost:5173` and `localhost:3000` are always allowed and
don't need listing.

## 5. Cloud differences worth knowing

**RAG grounding is off.** The deployed image installs `requirements-prod.txt`,
which omits `sentence-transformers` — with PyTorch the image exceeds ~2 GB and
free tiers reject it. `app/rag/embedder` detects the missing import, disables
itself, and the retriever returns no chunks. The tutor still personalises from
the learner profile, mastery data and conversation history; only reference
grounding is lost. Nothing errors.

**SearXNG is not deployed.** `/references` is the only affected endpoint, and
no screen currently calls it.

**Free-tier cold starts.** Render idles a free service after inactivity, so the
first request can take 30–60 seconds. Subsequent requests are normal. Worth
knowing before a live demo — hit `/health` a minute beforehand.

**pgvector on managed Postgres.** The initial migration runs
`CREATE EXTENSION IF NOT EXISTS vector`, which needs the extension available on
the server. Render's Postgres ships it. If you host the database elsewhere,
confirm pgvector is offered before deploying, or the migration will fail on the
`Vector(384)` column.

## 6. Environment variables

| Variable | Required | Used by | Notes |
|---|---|---|---|
| `GROQ_API_KEY` | Yes | Backend | Chat and quiz generation fail without it |
| `JWT_SECRET` | Yes | Backend | Long random string; Render generates one |
| `DATABASE_URL` | Cloud | Backend | Takes precedence over the `POSTGRES_*` set |
| `POSTGRES_DB` / `_USER` / `_PASSWORD` / `_HOST` / `_PORT` | Local | Backend, db | Compose defaults are fine |
| `CORS_ORIGINS` | Cloud | Backend | Comma-separated; localhost always allowed |
| `AUTO_MIGRATE` | No | Entrypoint | Defaults to `1`; `0` skips migrate and seed |
| `GROQ_MODEL` | No | Backend | Defaults to `openai/gpt-oss-20b` |
| `LLM_PROVIDER` | No | Backend | Only `groq` is implemented |
| `SEARXNG_URL` | No | Backend | Empty disables `/references` |
| `VITE_API_URL` | Yes | Frontend | Build-time; redeploy after changing |

## 7. Post-deployment checklist

- [ ] `GET /health` returns `{"status":"ok"}`
- [ ] `GET /health/db` reports `connected`
- [ ] `/docs` lists all 24 endpoints with response schemas
- [ ] Sign-up succeeds and returns a token
- [ ] Onboarding placement quiz submits and assigns a level
- [ ] Dashboard renders all 25 concepts across 5 tiers — if empty, the graph
      seed didn't run; check the `[entrypoint]` lines in the deploy logs
- [ ] A chat session generates an opening explanation
- [ ] A quiz generates, submits, and moves the concept's mastery bar
- [ ] Hard-refresh on `/chat/<id>` still loads (SPA rewrite is working)
- [ ] Browser console shows no CORS errors

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Dashboard is empty, no concepts | Graph seed didn't run | Check `[entrypoint]` logs; run `python -m app.data.seed_graph` |
| `type "vector" does not exist` | pgvector unavailable on the server | Use a Postgres that offers pgvector |
| Every request fails CORS | `CORS_ORIGINS` unset or stale | Set it to the exact frontend origin, redeploy |
| 404 on refreshing `/chat/<id>` | SPA rewrite not applied | Vercel Root Directory must be `frontend` |
| 502 from chat or quiz | LLM returned unparseable output twice | Usually transient; retry. Persisting means a bad `GROQ_API_KEY` |
| First request hangs ~60s | Free-tier cold start | Expected; warm it before a demo |
| Backend won't start, DB logs unreachable | Postgres slower than 60s to accept | Restart the service; the database is ready by then |
