# APPENDIX

## Appendix A — User Manual

### A.1 Getting started

**Creating an account.** Open the application and select *Sign up*. Provide a
name, email address and password. You are signed in immediately and taken to
onboarding.

**Onboarding, step 1 — preferences.** Four questions determine how the tutor
addresses you:

| Setting | Options | Effect |
|---|---|---|
| Learning style | Visual, Reading, Example-first, Theory-first | Whether explanations open with a diagram, prose, a worked example, or the concept |
| Pace | Quick, Moderate, Detailed | How much detail is included per step |
| Explanation detail | Concise, Standard, Verbose | Overall response length |
| Analogies | On or off | Whether real-world comparisons are used |

None of these is permanent — all can be changed later from the Profile page,
and they take effect on your next message.

**Onboarding, step 2 — placement quiz.** Ten multiple-choice questions spanning
foundational to advanced material. Answer honestly: the purpose is to calibrate
the starting point, not to score you. Guessing well only means the tutor starts
you further along than you are ready for. You can move back and forth between
questions before submitting.

**Onboarding, step 3 — results.** Your score and assessed starting level. Your
knowledge graph is seeded from your per-concept performance.

### A.2 The dashboard

The dashboard is the main screen, showing all 25 DSA concepts in five tiers
from Foundations to Expert.

**Concept cards** show the concept name, a short description, a mastery bar,
and any prerequisites. The bar is colour-coded: grey for untouched, red below
40%, amber below 75%, green above.

**Locked concepts** show a padlock when a prerequisite is below 60% mastery.
You may still open a locked concept — the tutor will simply assume the
foundation is missing and compensate.

**Recommended next** suggests one concept: your weakest unlocked, unmastered
one, easiest tier first among ties.

**Your progress** shows total points, overall accuracy and your strongest
topic.

**Review badge** turns amber with a count when concepts are due for revision.

### A.3 Learning in a session

**Starting a session.** Either click a concept and select *Start session*, or
go to *Sessions* and click *+ New* for a free-form topic. Concept-linked
sessions update your mastery graph; free-form sessions accumulate points only.

Choose a starting level — suggested from your current mastery, and
overridable.

**Conversing.** Type a question and press Enter; Shift+Enter inserts a
newline. Responses render as markdown with syntax-highlighted code. First
responses take a few seconds while the tutor is generated.

**"Why this response."** Beneath each tutor message is a small expandable
indicator showing which signals shaped it — your learning style, concepts you
have struggled with, memory of earlier sessions, how many reference
explanations were drawn on. Click to expand.

**Quizzes.** Click *Generate quiz* at any point. Questions target your recorded
weak areas where any exist. Select an option and submit; the correct answer,
an explanation, and a hint if you were wrong are then revealed. *Next question*
continues. Correct answers in a concept-linked session raise mastery and push
the concept's next review further out; incorrect answers bring it back
tomorrow.

**Managing sessions.** The sidebar lists your sessions. Hover to reveal a
delete control. Deletion removes the conversation and its quizzes; your points,
mastery and study streak are unaffected.

### A.4 Review

The *Review* page lists concepts due for revision, most overdue first, each
with its mastery level, current interval and last review date. *Start review*
opens a session pinned to that concept at a level matched to your mastery. The
schedule updates when you answer a quiz inside that session — a review is
counted on evidence, not on having opened the page.

### A.5 Profile

Shows sessions completed, study streak, and counts of strong and weak areas;
strengths and weaknesses by name; the tutor's accumulated memory of how you
learn; and editable preferences. Changes apply from your next message onward.

### A.6 Troubleshooting

| Problem | Cause and remedy |
|---|---|
| "Tutor is thinking…" for a long time | Generation takes 2–6 seconds. Beyond ~30 seconds, the hosted service may be waking from idle — wait and retry |
| "The tutor returned a response we couldn't parse" | A transient model fault. Send the message again |
| Dashboard shows no concepts | The knowledge graph was not seeded. See Appendix B |
| Signed out unexpectedly | Sessions last 24 hours. Sign in again |
| Streak shows 0 despite recent study | Streaks count consecutive days; one full missed day resets it |

## Appendix B — Installation Guide

### B.1 Prerequisites

- Docker Desktop, running
- Node.js 18 or newer
- A Groq API key from [console.groq.com](https://console.groq.com) (free)

### B.2 Installation

```bash
# 1. Clone and configure
git clone https://github.com/its-wasp/personal-adaptive-tutor.git
cd personal-adaptive-tutor
cp .env.example .env
#    Edit .env: set GROQ_API_KEY and JWT_SECRET

# 2. Start the backend stack (database, API, search)
docker compose up
#    Wait for "Application startup complete".
#    Migrations and knowledge-graph seeding run automatically.

# 3. Start the frontend, in a second terminal
cd frontend
npm install
npm run dev

# 4. Open http://localhost:5173
```

### B.3 Verification

```bash
curl http://localhost:8000/health        # {"status":"ok"}
curl http://localhost:8000/health/db     # {"status":"ok","database":"connected"}
python backend/scripts/smoke_test.py     # full end-to-end suite
```

Interactive API documentation is at <http://localhost:8000/docs>.

### B.4 Optional — reference content for RAG

```bash
docker compose exec backend python -m app.rag.content_seeder
```

Approximately ten minutes; safe to interrupt and re-run.

### B.5 Running the test suites

```bash
cd backend  && pytest -v --cov=app
cd frontend && npm test
```

### B.6 Common installation problems

| Symptom | Remedy |
|---|---|
| `type "vector" does not exist` | The database is not the pgvector image. Run `docker compose down -v` and start again |
| Dashboard empty after signup | Seeding did not run. Check `[entrypoint]` lines in the logs, or run `docker compose exec backend python -m app.data.seed_graph` |
| Port 5432 already allocated | A local PostgreSQL is running. Stop it, or change the host port in `docker-compose.yaml` |
| Chat returns HTTP 502 | `GROQ_API_KEY` is missing or invalid |
| Frontend cannot reach the API | Confirm the backend is up and `VITE_API_URL` matches |
